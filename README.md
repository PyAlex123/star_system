# ⭐ Школьная система наград

Учитель ставит звёзды за уроки, дети видят свой баланс, место в рейтинге класса, параллели и школы и копят
на призы. Вход для детей — только через Telegram: ребёнок сканирует QR со своей карточки,
попадает в бота и одной кнопкой открывает личный кабинет.

```
Карточка с QR  →  Telegram-бот  →  кнопка «Зайти в свой кабинет»  →  кабинет (Web App)
```

---

## Что умеет

**Главная** (`/`) — выбор «Я ученик» / «Я учитель».

**Пять тем оформления** — у каждой школы своя: «Тетрадь отличника», «Звёздный квест»,
«Созвездие», «Ясно и быстро» (светлая и тёмная), «Стикербук». Тему выбирают администратор
и учителя школы; её видят ученики, журнал и печатные карточки. Дизайн — `docs/design/`.

**Панель** (`/teacher`, вход по логину и паролю). Три роли: **администратор** — всё;
**учитель** — свои школы; **администрация школы** (директор, завуч) — свои школы только для
чтения: статистика, расписание, уроки, без паролей и QR учеников.
- журнал урока: до 10 ⭐ на класс за день, до 5 ⭐ одному ученику; ввод с клавиатуры
  (0–5, ↑/↓, Enter, Ctrl+Enter) и подтверждение «Итог урока»;
- вкладка «Уроки»: отменить ошибочное начисление одному ученику или всему уроку; видно, кто провёл урок;
- **расписание**: занятия со звёздами по дням недели (класс, время, кабинет, учитель); журнал
  подсказывает, какие уроки сегодня, ученик видит свой следующий урок;
- **статистика** школы за 7/30/90 дней или всё время: звёзды и призы, уроки «по расписанию: N из M»,
  классы по параллелям, рейтинг «школа · параллель · класс», «давно без звёзд», учителя;
- **активность ученика**: звёзды по неделям, серия уроков со звёздами, последний заход в кабинет;
- «скрыть из рейтинга» — звёзды копятся, но в топе ученика не видно;
- классы (сетка 1–11 × А–Д), ученики, шаблон Excel: загрузка и выгрузка журнала;
- сотрудники со своими логинами (учитель или администрация школы); выданный пароль виден
  администратору в списке, пока сотрудник не сменит его сам;
- выдача призов и списание звёзд;
- витрина призов: добавить (**сразу с фотографией**), изменить, скрыть, заменить фото;
- печать карточек класса с QR-кодами: лист А4 по 8 карточек, метки реза, выборочная печать;
- для каждого ученика: показать QR, открыть **его кабинет глазами ученика**, выпустить
  новый код, отвязать Telegram, сбросить аватар;
- **логин и пароль для входа через сайт**: выдаются автоматически, видны в окне
  «Данные для входа», там же меняются и выдаются заново.

**Мониторинг** (вкладка панели и страница `/m/<код школы>`)
- опрос на 1–2 минуты урока: настроение, понимание темы, темп, «Выходной билет» по целям урока;
- 15 стандартных вопросов и 4 готовых набора; запуск — два нажатия, класс подставляется по расписанию;
- ученики отвечают по постоянной ссылке школы без входа и пароля; есть код урока из 4 цифр;
- экран для класса (проектор): ссылка, QR, таймер, кто ответил, гости и повторы имён;
- итоги по каждому вопросу; результаты видят автор опроса и администратор.

**Вход ученика — два способа**
- **через Telegram**: QR с карточки → бот → кнопка «Зайти в свой кабинет»;
- **через сайт** (`/enter`): логин и пароль с той же карточки — для тех, у кого нет
  Telegram. Пароль ребёнок может сменить сам, учитель — выдать новый.

**Кабинет ученика** (`/app`, Telegram Web App)
- баланс звёзд и прогресс до ближайшего приза;
- **топ-5 класса, параллели и школы** с пьедесталом — по звёздам, заработанным за всё время
  (забрал приз — место не падает); если ученик не в пятёрке — его строка показывается отдельно,
  плюс подсказка, сколько звёзд до следующего места;
- «Моя активность»: следующее занятие, звёзды за неделю и 30 дней, серия, столбики по неделям;
  «Мои занятия» — расписание класса в профиле;
- витрина призов с фотографиями и прогрессом;
- история начислений и списаний;
- **24 аватара** на выбор, своё фото или фото профиля Telegram;
- смена пароля и выход из аккаунта (открепляет Telegram, звёзды остаются);
- праздник, когда звёзд хватает на приз, и уведомление о новых звёздах;
- оформление — тема школы; у «Ясно и быстро» светлая, тёмная или как в Telegram;
- внутри Telegram свайп вниз не закрывает кабинет случайно.

## Локальный запуск

```bash
python -m venv .venv
.venv/Scripts/python.exe -m pip install -r requirements.txt

cp .env.example .env        # заполните TEACHER_PASSWORD
.venv/Scripts/python.exe app.py
```

Откройте http://localhost:8000 — попросит пароль учителя.
Если `TEACHER_PASSWORD` в `.env` пуст, временный пароль печатается в окне сервера при запуске.

Картинки лежат в репозитории. Пересоздать их:

```bash
.venv/Scripts/python.exe scripts/make_avatars.py        # 24 SVG-аватара
.venv/Scripts/python.exe scripts/fetch_prize_photos.py  # фото товаров -> WebP
```

## Развёртывание на сервере

Ниже — порядок для случая «Linux + Docker, nginx уже обслуживает другие сайты,
система живёт на подпути `/stars`». Все команды выполняются на сервере.

### Шаг 1. Разведка

```bash
git clone <адрес-вашего-репозитория> /opt/school-stars
cd /opt/school-stars
bash deploy/check-server.sh
```

Скрипт ничего не меняет — он печатает версию Docker, где работает nginx, занят ли порт 8000
и какие домены есть в сертификатах. По его выводу выбирается конфиг nginx.

### Шаг 2. Настройки

```bash
cp .env.example .env
nano .env
```

Минимум, что нужно заполнить:

```ini
BASE_URL=https://ваш-домен.ru
URL_PREFIX=/stars
TEACHER_PASSWORD=придумайте-длинный-пароль
BOT_TOKEN=1234567890:AA...
BOT_USERNAME=school_stars_bot
USE_WEBHOOK=1
DEV_LOGIN=0
```

> Если `BASE_URL` начинается с `https://`, а `TEACHER_PASSWORD` пуст — сервер откажется
> стартовать и скажет об этом. Это сделано специально: случайный пароль в логах
> на боевом сервере — ловушка.

### Шаг 3. Запуск контейнера

```bash
mkdir -p data
sudo chown -R 10001:10001 data     # контейнер работает не от root, UID 10001
docker compose up -d --build
docker compose logs -f             # Ctrl+C чтобы выйти из просмотра
```

Проверка, что приложение живо (порт слушает только localhost, снаружи он недоступен):

```bash
curl -s http://127.0.0.1:8000/healthz
```

### Шаг 4. nginx

Возьмите блок из `deploy/nginx-host.conf` (nginx на сервере) или `deploy/nginx-docker.conf`
(nginx в контейнере) и вставьте **внутрь существующего `server { ... }`** вашего сайта —
обычно это `/etc/nginx/sites-available/<ваш-сайт>`. Отдельный server-блок и новый
сертификат не нужны: домен и HTTPS у вас уже есть.

```bash
sudo nginx -t && sudo systemctl reload nginx
```

Два важных момента, они уже учтены в конфигах:

- **завершающий слэш** в `proxy_pass http://127.0.0.1:8000/;` — он срезает `/stars`,
  и приложение внутри работает так, будто живёт в корне;
- **`client_max_body_size 6m`** — без этого nginx обрежет загрузку фотографии приза
  на первом мегабайте и выдаст ошибку 413.

Теперь откройте `https://ваш-домен.ru/stars/` — должна появиться форма входа учителя.

### Шаг 5. Бот

1. Создайте бота у [@BotFather](https://t.me/BotFather): `/newbot`, имя (его видят дети),
   username (например `school_stars_bot`).
2. Токен и username впишите в `.env`, затем `docker compose restart`.
3. В логах должна появиться строка `Бот запущен (webhook)`.

Настраивать Menu Button в BotFather не нужно — кнопка приходит прямо в сообщении бота.

### Шаг 6. Карточки

1. В панели учителя выберите класс → **🖨 Карточки класса** → Печать.
2. Разрежьте лист и раздайте детям.
3. Ребёнок наводит камеру на QR → открывается бот → кнопка **«Зайти в свой кабинет»**.

Если камера не читает QR, ребёнок отправляет боту код с карточки (8 символов) — результат тот же.

**Карточка привязывается к первому аккаунту, который её отсканировал.** Чужой аккаунт получит
отказ. Потерял карточку — учитель жмёт ♻️ в журнале: старый код умирает, печатается новый.

## Обслуживание

**Обновление:**

```bash
cd /opt/school-stars
git pull
docker compose up -d --build
```

Данные при этом не трогаются — они в `data/`, а не в образе.

**Резервная копия** (база звёзд, опросы «Мониторинга» и фотографии):

```bash
bash deploy/backup.sh
```

Каждую ночь в 3:30 — добавьте в `crontab -e`:

```
30 3 * * * cd /opt/school-stars && bash deploy/backup.sh >> backups/backup.log 2>&1
```

**Восстановление:**

```bash
docker compose down
rm -rf data && tar -xzf backups/stars_2026-11-19_03-30.tar.gz
docker compose up -d
```

**Переезд в корень домена или на поддомен:** поменяйте `URL_PREFIX` в `.env` (пусто = корень),
поправьте `location` в nginx и перезапустите. Код трогать не нужно.

## Настройки `.env`

| Параметр | Зачем |
|---|---|
| `BASE_URL` | публичный адрес сайта без подпути |
| `URL_PREFIX` | подпуть (`/stars`) или пусто, если система в корне домена |
| `BOT_TOKEN` | токен от @BotFather. Пусто → бот не запускается, сайт работает |
| `BOT_USERNAME` | имя бота без `@`, из него собираются ссылки в QR |
| `USE_WEBHOOK` | `0` — long polling, `1` — webhook (нужен настоящий https-домен) |
| `TEACHER_PASSWORD` | пароль в панель учителя. На https обязателен |
| `JWT_SECRET` | подпись сессий. Пусто → создаётся `data/jwt_secret.txt` |
| `DEV_LOGIN` | `1` — вход в кабинет без Telegram: `/app?dev=<id>`. **На сервере держите `0`** |
| `SCHOOL_NAME` | печатается на карточках |
| `DATA_DIR` | где лежат данные. Пусто → `data/` рядом с проектом |

## Безопасность

- Панель учителя закрыта паролем (сессия в httpOnly-cookie на 12 часов). Администрация школы
  только смотрит: любой изменяющий запрос — 403, логинов, паролей и QR учеников ей не отдаётся.
- **Сессии ученика отзываются**: сброс пароля, новый код карточки, отвязка Telegram
  и выход завершают все выданные раньше сессии.
- Пароли хранятся хешем pbkdf2; хеши не уходят даже в панель учителя.
- **Перебор паролей ограничен**: 8 неудач на логин и 60 на адрес за 15 минут
  (вся школа обычно за одним IP — опечатки на уроке не блокируют класс).
- Фото детей хранятся под случайными именами и удаляются вместе с учеником.
- Страницы нельзя встроить в чужой сайт; кабинет — только в Telegram.
- Ученик получает **только свои данные** и топ-5 своего класса; полный список школы
  (`/api/state`) доступен лишь учителю.
- `initData` из Telegram проверяется по подписи HMAC-SHA256 и не принимается старше 24 часов.
- Webhook защищён секретом в адресе и заголовком `X-Telegram-Bot-Api-Secret-Token`.
- Загружаемые картинки проверяются Pillow и пересохраняются в WebP — файл с чужим
  расширением внутрь не попадёт. Лимит 5 МБ.
- Контейнер работает не от root (UID 10001), порт слушает только localhost.
- Схема API (`/docs`, `/openapi.json`) на https-адресе не публикуется.

> **Про общий домен.** На подпути система делит адрес с соседним сайтом, то есть у них
> общий origin. Страницы соседнего сайта технически смогут обращаться к `/stars/api/*`
> с cookie учителя. Если соседний сайт ваш — это не проблема. Если там чужой код
> (например, сторонний движок с плагинами), лучше вынести систему на отдельный
> поддомен: поменять `URL_PREFIX` на пустой и завести `stars.ваш-домен.ru`.
