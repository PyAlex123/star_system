# Архитектура проекта «Система наград»

Документ описывает, из чего состоит система, где что лежит и почему сделано именно так.
README отвечает на вопрос «как запустить и развернуть», этот файл — на вопрос «как это устроено
и куда смотреть, когда нужно что-то поменять».

Версия описания: 20 ноября 2026, коммит `d5beedf`.

---

## 1. Что это за система

Учёт звёзд (баллов) за уроки в школе и витрина призов, на которые звёзды тратятся.

Три роли, три разных входа:

| Кто | Где работает | Как входит | Что видит |
|---|---|---|---|
| **Учитель** | браузер на компьютере, страница `/` | пароль из `.env` | всё: школы, классы, учеников, уроки, призы |
| **Ученик** | Telegram, Web App по кнопке в боте | QR-код с карточки → бот → кабинет | только себя и топ-5 своего класса |
| **Бот** | Telegram | — | привязывает Telegram-аккаунт к ученику по коду |

Главный замысел: **ученик не вводит пароль**. Учитель печатает карточки класса, каждому ребёнку
достаётся свой QR. Ребёнок наводит камеру, попадает в бота, бот запоминает его Telegram-аккаунт
и показывает одну кнопку «Открыть кабинет».

## 3. Семь решений, которые определяют всё остальное

### 3.1. Бот живёт внутри процесса сайта

`backend/main.py` поднимает бота в `lifespan`-хуке FastAPI. Один процесс, один файл базы, никакой
синхронизации между процессами. Если запустить бота отдельно, два процесса начнут писать в один
JSON и затирать изменения друг друга.

Цена решения: нельзя включить `uvicorn --reload` — при перезапуске Telegram отдаёт
«terminated by other getUpdates request». Поэтому в `app.py` reload выключен с комментарием.

### 3.2. База — один JSON-файл, а не СУБД

Школа небольшая, данных мало, а установка и обслуживание PostgreSQL на общем сервере — отдельная
история. Защита от повреждения сделана двумя приёмами в `backend/db.py`:

- **`threading.RLock`** — все чтения и записи под одной блокировкой. Бот и панель учителя пишут
  из разных задач, без блокировки они бы перетирали друг друга.
- **Атомарная запись** — `tempfile.mkstemp` рядом с файлом, `fsync`, затем `os.replace`.
  Если сервер убьют посреди записи, останется либо старый файл, либо новый, но не обрезанный.

Функция `db.transaction(func)` — главный инструмент: читает, даёт изменить, записывает. Всё под
одной блокировкой. Если `func` вернула `db.NO_SAVE`, файл не перезаписывается.

### 3.3. Система живёт на подпути — и это настройка, а не код

Сайт опубликован как `домен/stars`, рядом на том же домене чужие сайты. Префикс задаётся
переменной `URL_PREFIX` в `.env`; в коде он нигде не зашит. Переезд на поддомен — правка одной
строки в `.env` и конфига nginx.

Работает так: **nginx срезает префикс**, приложение внутри живёт в корне.

```nginx
location /stars/ {
    proxy_pass http://127.0.0.1:8000/;   # ← слэш на конце и срезает /stars
}
```

**`root_path` у FastAPI специально НЕ задан** — об этом есть комментарий в `main.py`. Если его
выставить, Starlette вычтет префикс второй раз, и смонтированные каталоги `/static`,
`/static/uploads` начнут отдавать 404. Это была реальная поломка, не теория.

Внешние ссылки (QR-коды, адрес Web App, webhook) собираются через `config.site_url()`, который
префикс дописывает. Ссылки внутри HTML — через подстановку `{{BASE}}`.

### 3.4. Два шаблонных placeholder'а в HTML

`render_page()` в `main.py` при отдаче страницы заменяет:

- **`{{BASE}}`** → значение `URL_PREFIX`. Без этого `/static/css/theme.css` ушёл бы в корень
  чужого сайта. В JS то же значение приходит как `window.APP_BASE` и используется внутри
  функции `api()` — поэтому префикс добавлен в одном месте, а не в двадцати вызовах.
- **`{{ICONS}}`** → содержимое `static/img/icons.svg` целиком, сразу после `<body>`.
  Почему инлайном: внешний спрайт через `<use href="файл.svg#id">` не всегда грузится
  в WebView старых версий Telegram.

Результат кешируется в памяти по сумме mtime двух файлов — правки подхватываются без
перезапуска сервера.

### 3.5. Всё изменяемое — в одном каталоге `data/`

База, секрет сессий и загруженные картинки лежат в `DATA_DIR` (по умолчанию `data/`).
Следствия: в Docker монтируется **один** том, а бэкап — это копия одной папки.

В `config.py` есть `_migrate_legacy_data()` — разовый перенос со старой раскладки, когда
`stars_db.json` и `static/uploads/` лежали в корне проекта. Нужен, чтобы при обновлении
не потерялись накопленные звёзды.

Загрузки отдаются отдельным монтированием: `/static/uploads` → `DATA_DIR/uploads`.
Оно объявлено **раньше** общего `/static` — Starlette ищет совпадение по порядку.

### 3.6. Иконки — SVG, эмодзи остались только в боте

В веб-интерфейсе ни одного эмодзи: 37 символов в `icons.svg`, рисуются линией 1.75,
цвет наследуют через `currentColor`. В обоих JS-файлах есть хелпер `icon(name, cls)`.

В сообщениях бота эмодзи оставлены сознательно — Telegram умеет показывать только текст
и эмодзи, SVG туда не вставить.

### 3.7. Дизайн сознательно отходит от типовых приёмов

Правила перечислены в шапке `static/css/theme.css`, потому что их легко нарушить случайно:

| Правило | Как сделано |
|---|---|
| Никаких сине-фиолетовых градиентов | плоская заливка, палитра бумага / чернила / густой зелёный / янтарь |
| Разделение границами, а не размытыми тенями | одна короткая тень `--shadow-pop`, только у модальных окон |
| Радиусы разные по назначению | поле 6px, кнопка 8px, панель 14px — не «всё по 16» |
| Заголовки разделов | мелкая прописная надпись с разрядкой + тонкая линейка (`.eyebrow`) |
| Цифры | шрифт с засечками, моноширинные по ширине знака |

Шрифты лежат **в проекте**, не на CDN: школьная сеть может резать внешние запросы.
Кириллица и латиница разнесены по `unicode-range`, чтобы не тянуть лишнее.

## 4. Схема данных

Файл `data/stars_db.json`, текущая версия схемы — **3**.

```jsonc
{
  "version": 4,
  "schools":  [ { "id": 1, "name": "Наша школа" } ],
  "classes":  [ { "id": 1, "school_id": 1, "name": "5-А" } ],
  "students": [
    {
      "id": 101,
      "class_id": 1,
      "name": "Иванов Артём",
      "total_stars": 34,
      "token": "K7MPQ2XZ",            // код для QR-карточки, 8 символов
      "login": "ivanov.artem",        // вход через сайт
      "password_hash": "pbkdf2_sha25620000$...",
      "password_shown": "kvant3432",  // открытый пароль; null после смены ребёнком
      "tg_id": null,                   // Telegram-аккаунт после привязки
      "tg_username": null,
      "bound_at": null,
      "avatar": { "type": "preset", "value": "fox" },
      "history": [ { "date": "2026-11-10", "delta": 4, "reason": "Активность на уроке" } ]
    }
  ],
  "prizes": [
    { "id": 1, "name": "…", "cost": 70, "category": "electronics",
      "desc": "…", "image": "/static/img/prizes/znatok-999.webp", "active": true }
  ],
  "lessons": [
    { "class_id": 1, "class_name": "5-А", "school_name": "Наша школа",
      "date": "2026-11-20", "total_stars": 8, "students_rewarded": 3 }
  ],
  "settings": {}
}
```

Важные детали:

- **Иерархия школа → класс → ученик.** Класс — объект с `id`, ученик ссылается через `class_id`.
  Поэтому класс можно переименовать, не трогая учеников, а «5-А» может существовать
  в двух разных школах одновременно.
- **В уроке хранятся названия, а не только id.** `class_name` и `school_name` — снимок
  на момент урока: класс потом переименуют, а история должна остаться читаемой.
- **`token`** — алфавит без символов, которые дети путают при ручном вводе: нет `O`/`0`, `I`/`1`.
- **`avatar.type`** принимает три значения: `preset` (ключ из `AVATAR_PRESETS`),
  `photo` (загруженный файл) и `telegram` (ссылка на фото профиля).

### Миграции

`db.migrate(db)` вызывается при каждой загрузке базы и **идемпотентна**: дописывает
недостающие поля и возвращает `True`, если что-то изменилось (тогда файл сохраняется).

- **v1 → v2**: у учеников появились `token`, `tg_id`, `avatar`, `history`.
- **v3 → v4**: вход через сайт. Каждому ученику выдаются `login` (транслит ФИО) и пароль;
  существующие записи получают их при первой загрузке базы после обновления.
- **v2 → v3**: `_migrate_to_schools()` — плоский список строк `["5-А", "5-Б"]` превращается
  в объекты с `id`, создаётся школа из `SCHOOL_NAME`, у учеников `class_name` → `class_id`,
  в уроках дописывается `class_id`.

Новое поле добавляется так: дописать в `DEFAULT_DB`, дописать проверку в `migrate()` —
и старая база подтянется сама.

## 5. Карта API

Все адреса — **внутренние**, без префикса. Снаружи к ним добавляется `URL_PREFIX`.

### Страницы

| Адрес | Файл | Доступ |
|---|---|---|
| `GET /` | `teacher.html` | учитель, иначе 307 на `/login` |
| `GET /login` | `login.html` | открыт |
| `GET /app` | `app.html` | открыт (сами данные — только после проверки initData) |
| `GET /enter` | `enter.html` | открыт — вход ученика по логину и паролю |
| `GET /cards/{class_id}` | генерируется в `cards.py` | учитель |
| `GET /healthz` | JSON о состоянии | открыт |
| `GET /docs` | Swagger | **только если `BASE_URL` не https** |

### Вход — `backend/routers/auth.py`

| Метод | Адрес | Что делает |
|---|---|---|
| POST | `/api/auth/twa` | проверяет `initData` из Telegram, выдаёт JWT ученика на 30 дней |
| POST | `/api/auth/student` | логин и пароль → JWT ученика; защищён от перебора |
| POST | `/api/auth/teacher` | пароль → httpOnly-cookie на 12 часов; защищён от перебора |
| POST | `/api/auth/teacher/logout` | удаляет cookie |
| POST | `/api/auth/preview?student_id=` | учитель смотрит кабинет глазами ученика |
| POST | `/api/auth/dev?student_id=` | отладочный вход; при `DEV_LOGIN=0` отдаёт 404 |

### Панель учителя — `backend/routers/teacher.py`

Весь роутер закрыт зависимостью `require_teacher`.

| Метод | Адрес | Примечание |
|---|---|---|
| GET | `/api/state` | вся база одним запросом — панель рисуется на клиенте |
| POST / PATCH / DELETE | `/api/schools`, `/api/schools/{id}` | удаление каскадное: классы, ученики, уроки. Единственную школу удалить нельзя |
| POST / PATCH / DELETE | `/api/classes`, `/api/classes/{id}` | `POST` требует `school_id`; названия уникальны внутри школы |
| POST | `/api/students` | по `class_id` |
| POST | `/api/students/bulk` | импорт из Excel: `school_id` + `class_name`, классы создаются сами |
| DELETE | `/api/students/{id}` | |
| POST | `/api/students/{id}/move?class_id=` | перевод в другой класс |
| POST | `/api/students/{id}/reset-token` | новый код → старый QR перестаёт работать |
| POST | `/api/students/{id}/unbind` | отвязать Telegram (телефон сменили, аккаунт чужой) |
| PATCH | `/api/students/{id}` | переименовать ученика или сменить ему логин |
| POST | `/api/students/{id}/password` | выдать новый пароль; пустое поле — сгенерировать |
| POST | `/api/students/{id}/reset-avatar` | сбросить аватар |
| POST | `/api/lessons/complete` | **лимиты: 10 звёзд на урок, 5 на ученика** (`config.py`) |
| POST | `/api/students/deduct` | списание при выдаче приза; проверяет, что звёзд достаточно |

### Призы — `backend/routers/prizes.py`

Весь роутер — только учитель.

| Метод | Адрес |
|---|---|
| POST / PATCH / DELETE | `/api/prizes`, `/api/prizes/{id}` |
| POST | `/api/prizes/{id}/photo` — загрузка, сжатие в 800×600 WebP |
| DELETE | `/api/prizes/{id}/photo` |

Удаление приза и удаление фото обязательно чистят файл с диска (`_drop_photo_file`), иначе
в `data/uploads/prizes/` копились бы картинки удалённых призов.

### Кабинет ученика — `backend/routers/me.py`

Закрыт зависимостью `require_student` (JWT в заголовке `Authorization: Bearer`).

| Метод | Адрес | Что отдаёт |
|---|---|---|
| GET | `/api/me` | всё для кабинета одним запросом: свои данные, топ-5, призы, история, список аватаров |
| POST | `/api/me/avatar` | пресет или фото профиля Telegram |
| POST | `/api/me/photo` | своё фото: обрезка в квадрат 320 px |
| POST | `/api/me/unbind` | выход из аккаунта: открепляет Telegram от карточки |
| POST | `/api/me/password` | ребёнок меняет себе пароль (нужен текущий) |

Выход **не удаляет ничего ценного**: звёзды, история и аватар остаются, обнуляются только
`tg_id`, `tg_username` и `bound_at`. Ребёнок возвращается по тому же QR-коду.

Эндпоинт отказывает (403), если токен выдан предпросмотром учителя — иначе учитель,
листая кабинет ребёнка, отвязал бы его аккаунт. См. claim `prv` ниже.

**Что ученику не отдаётся:** функция `public_card()` в строке рейтинга намеренно не содержит
истории, кода карточки и Telegram-данных одноклассников. Полный список школы — только у учителя.

Логика рейтинга в `build_leaderboard()`: сортировка по звёздам, при равенстве — по алфавиту.
Если ученик не попал в топ-5, его строка добавляется отдельно (`me`), чтобы он видел своё место.
`gap_to_next` — сколько звёзд до того, кто выше.

### Карточки и QR — `backend/routers/cards.py`

| Метод | Адрес |
|---|---|
| GET | `/api/students/{id}/qr.png?size=` — PNG, `Cache-Control: no-store` |
| GET | `/cards/{class_id}` — печатная страница A4 |

Название школы берётся **из базы** (`db.school_name_of_class`), а не из `.env` — школ теперь много.
Если `BOT_USERNAME` не заполнен, на странице печатается предупреждение: QR будут вести на сайт,
а не в бота.

### Webhook — `backend/routers/telegram.py`

`POST /telegram/{secret}`. Три уровня защиты:

1. при `USE_WEBHOOK=0` маршрут отдаёт **404** — снаружи не видно, что такая возможность есть;
2. секрет в пути сверяется через `hmac.compare_digest`; не совпал — тоже 404;
3. Telegram дублирует секрет в заголовке `X-Telegram-Bot-Api-Secret-Token`; не совпал — 403.

Секрет выводится из хеша токена бота (`config.WEBHOOK_SECRET`): значение стабильно между
перезапусками, снаружи не угадывается, отдельный файл не нужен.

## 6. Авторизация и безопасность

### Ученик: Telegram Web App

`security.validate_init_data()` реализует спецификацию Telegram:

```
secret_key = HMAC_SHA256(ключ="WebAppData", сообщение=BOT_TOKEN)
hash       = HMAC_SHA256(ключ=secret_key,  сообщение=data_check_string)
```

Дополнительно проверяется свежесть `auth_date` — не старше 24 часов. Подделать initData
без токена бота нельзя.

Дальше ищется ученик по `tg_id`. Если аккаунт не привязан — **403 с понятным текстом**
«отсканируй свой QR-код с карточки класса», а не абстрактная ошибка.

### Вход через сайт — для детей без Telegram

Второй способ входа, равноправный с Telegram. Логин выдаётся автоматически из фамилии и имени
(`Иванов Артём` → `ivanov.artem`, при совпадении добавляется число), пароль — произносимое слово
с четырьмя цифрами (`kvant3432`). И то и другое печатается на карточке рядом с QR-кодом.

**Пароль хранится хешем** — pbkdf2-sha256, 120 000 итераций, своя соль у каждого
(`backend/passwords.py`). Отдельной зависимости вроде bcrypt не заводили: всё есть в стандартной
библиотеке, а лишний пакет в образе — лишний риск.

**Открытый пароль хранится ровно до первой самостоятельной смены.** Поле `password_shown` нужно,
чтобы учитель мог перепечатать карточку и подсказать забывшему. Как только ребёнок задаёт свой
пароль через кабинет, поле обнуляется: дальше пароль знает только он, а учителю остаётся
выдать новый.

**Перебор ограничен** (`backend/ratelimit.py`): 8 неудач за 15 минут — и адрес блокируется.
Счёт идёт и по IP, и по логину, поэтому не поможет ни долбить один аккаунт, ни веером перебирать
класс. Ответ при неверном логине и при неверном пароле **одинаковый** — иначе по разнице ответов
можно было бы собрать список логинов. Счётчик живёт в памяти процесса и обнуляется при
перезапуске: для школы этого достаточно, внешнее хранилище не нужно.

### Сессии

JWT, алгоритм HS256, библиотека PyJWT. Секрет — из `.env` или из `data/jwt_secret.txt`
(создаётся при первом запуске, чтобы перезапуск сервера не выбрасывал детей из кабинета).

- **Ученик**: токен на 30 дней, передаётся в заголовке, дублируется в `sessionStorage`
  (чтобы не переавторизовываться при каждом открытии вкладки).
  - Токен предпросмотра, который получает учитель через `/api/auth/preview`, несёт claim
    **`prv: true`**. Без него он был бы неотличим от настоящего. `require_student`
    выставляет `request.state.student_preview`, и действия «только для себя»
    (сейчас это выход из аккаунта) предпросмотру запрещены.
  - Выданный токен после выхода из аккаунта **не аннулируется** — он просто перестаёт
    быть у кого-либо на руках, так как клиент его стирает. Отзыв токенов потребовал бы
    версии сессии в записи ученика; для школы это сочтено излишним.
- **Учитель**: cookie `teacher_session` на 12 часов, `httpOnly`, `SameSite=Lax`.
  - `secure` берётся из **схемы `BASE_URL`**, а не из схемы запроса: за nginx приложение
    всегда видит http и поставило бы cookie без флага.
  - `path = URL_PREFIX or "/"` — на общем домене cookie не улетает к соседним сайтам.

### Боевые предохранители (`config.py`)

- `BASE_URL` начинается с `https://`, а `TEACHER_PASSWORD` пуст → **сервер не стартует**
  с объяснением. Молча придумать случайный пароль на сервере — ловушка: после перезапуска
  контейнера учитель не войдёт.
- При https `/docs` и `/openapi.json` отключены.
- `DEV_LOGIN` на сервере обязан быть `0`: иначе посторонний откроет кабинет любого ребёнка.
- `.env` читается с `encoding="utf-8-sig"`. Без этого python-dotenv берёт кодировку системы
  (на русской Windows cp1251) и кириллица в названии школы или пароле ломается; `-sig`
  вдобавок срезает BOM, который добавляют Блокнот и PowerShell.

### Что остаётся известным компромиссом

Система делит origin с соседними сайтами того же домена. Их страницы технически могут
слать запросы к `/stars/api/*` с cookie учителя. Если соседние сайты ваши — это не проблема.
Поддомен был бы строже; подпуть выбран сознательно.

### Загрузка файлов

`backend/images.py`: лимит 5 МБ (`read_upload` читает на один байт больше и обрывается),
проверка, что это действительно картинка (`Image.load()`, белый список форматов),
`ImageOps.exif_transpose` — иначе фото с телефона ляжет боком. Результат всегда
перекодируется в WebP, то есть исходный файл на диск не попадает.

В nginx обязателен `client_max_body_size 6m` — по умолчанию он режет на 1 МБ,
и загрузка 5-мегабайтного фото упала бы с 413. В обоих готовых конфигах это уже прописано.

## 7. Бот: путь ребёнка в кабинет

```
карточка с QR  →  t.me/бот?start=K7MPQ2XZ  →  /start с кодом  →  привязка tg_id
                                                                      ↓
                                      кнопка «Открыть кабинет» (web_app)
                                                                      ↓
                                    /app → initData → JWT → GET /api/me
```

`handlers.py`, функция `bind_by_code()` различает четыре исхода:

| Исход | Что происходит |
|---|---|
| `ok` | код свободен — привязываем, пишем `tg_id`, `tg_username`, `bound_at` |
| `already_me` | этот аккаунт уже привязан к этому ученику — просто открываем кабинет |
| `taken` | код уже использован другим аккаунтом — просим обратиться к учителю |
| `not_found` | кода нет в базе |

Коды сверяются **без учёта регистра**: ребёнок может ввести их руками, если камера не читает QR.

Кнопка `web_app` добавляется только если адрес кабинета начинается с `https://` — Telegram
отказывается открывать Web App по http. Локально поэтому кнопки нет, и это ожидаемо.

### Два режима

| | polling (`USE_WEBHOOK=0`) | webhook (`USE_WEBHOOK=1`) |
|---|---|---|
| Когда | разработка, небольшая школа | боевой сервер с https |
| Требования | ничего | настоящий домен с сертификатом |
| Как | `dp.start_polling` в фоновой задаче | Telegram шлёт на `/telegram/{секрет}` |

Если `USE_WEBHOOK=1`, но `BASE_URL` не https, бот **не запускается** и пишет понятную
ошибку в лог — Telegram такой адрес всё равно не примет.

## 8. Клиентская часть

Фреймворков нет. Три страницы, два скрипта, четыре файла стилей. Причина простая: система
маленькая, а сборка (npm, бандлер, версии) добавила бы больше работы, чем сэкономила.

### Панель учителя — `teacher.html` + `teacher.js`

Три раздела, переключаются `switchPage()`: **журнал**, **призы**, **история уроков**.

Состояние — четыре переменные в начале `teacher.js`:

```js
let state = { schools: [], classes: [], students: [], prizes: [], lessons: [] };
let activeSchool = null;   // id выбранной школы
let activeClass  = null;   // id выбранного класса
let draft = {};            // { student_id: звёзды за текущий урок }
```

`loadState()` забирает всю базу одним `GET /api/state`, `renderAll()` перерисовывает интерфейс.
После любого изменения — снова `loadState()`. Для нескольких классов этого достаточно
и гораздо проще, чем точечные обновления DOM.

Отдельно стоит знать про:

- **`.scope-bar`** — выбор школы (`#schoolSelect`) и вкладки классов. Кнопки добавления,
  переименования и удаления есть и у школы, и у класса.
- **Банк урока** — `usedBank()` и `renderBank()` следят, чтобы сумма не превысила 10 звёзд.
  Лимит дублируется на клиенте (`MAX_LESSON_BANK`) для подсказки, но решает всё равно сервер.
- **Импорт** — `parseLines()` разбирает вставленный из Excel текст и отдаёт
  `{school_id, class_name, name, total_stars}`; классы на сервере создаются сами.
  Есть и `importCsv()` / `exportCsv()` (экспорт включает колонки школы и класса).
- **Фото приза при создании** — файл держится в `prizePhotoFile`, превью рисуется через
  `URL.createObjectURL`. После создания приза `savePrize()` берёт `id` из ответа и
  отправляет файл вторым запросом на `/api/prizes/{id}/photo`.

### Кабинет ученика — `app.html` + `app.js`

Четыре вкладки: **призы**, **рейтинг**, **история**, **профиль**.
Можно открыть сразу нужную: `/app?view=rating`.

- `authenticate()` — три пути входа: initData из Telegram, `?preview=` (учитель смотрит
  глазами ученика), `?code=` для отладки.
- `insideTelegram = Boolean(tg?.initData)` — важная строка. Заглушка `telegram-web-app.js`
  вне Telegram сообщает `colorScheme: "light"`, из-за чего тёмная тема принудительно
  переключалась в светлую. Поэтому `applyTelegramTheme()` выходит сразу, если мы не в Telegram.
- `celebrateNewPrizes()` и `sparkle()` — анимация, когда приз стал доступен.
  Набор доступных призов запоминается в `affordableBefore`, чтобы не праздновать дважды.
- `plural()` — русские формы: «1 звезда / 2 звезды / 5 звёзд». Текст
  «поднимешься на N-е место в классе» подставляется числом, а не фамилией: фамилию
  пришлось бы склонять.

### Стили

| Файл | Что внутри |
|---|---|
| `theme.css` | шрифты, токены цвета, светлая и тёмная тема, кнопки, `.ic`, `.eyebrow`, `.tag`, `.panel`, `.num` |
| `teacher.css` | таблица журнала, вкладки классов, модальные окна, сетка призов |
| `app.css` | hero, пьедестал, строки рейтинга, карточки призов, таймлайн, лист выбора аватара |
| `cards.css` | печать |

Тёмная тема переопределяет токены в двух местах: `@media (prefers-color-scheme: dark)`
под защитой `:root:not([data-theme="light"])` и в `:root[data-theme="dark"]` — второе
нужно, потому что Telegram сообщает тему атрибутом.

Две детали, которые легко сломать повторно:
- `[hidden] { display: none !important; }` — без этого класс `.screen { display: flex }`
  побеждал атрибут, и скрытые экраны оставались видны.
- У `.hero` нижняя граница задана `rgba(0,0,0,.3)`, а не `var(--ink)`: в тёмной теме
  чернила светлые, и граница превращалась в яркую полосу.

**`cards.css` — единственный файл с зашитыми цветами.** Карточки печатают на белой бумаге;
если брать цвета из темы, в тёмном режиме на печать уйдёт тёмный фон.

### Кеширование

Middleware `cache_headers` в `main.py`:

| Что | Заголовок | Почему |
|---|---|---|
| `/static/*.css`, `*.js` | `no-cache` | иначе после обновления системы у детей останется старый кабинет |
| `/static/uploads/` | `max-age=300` | фото могут заменить |
| остальная статика | `max-age=604800` | шрифты и аватары не меняются |

## 9. Статические ресурсы

### Аватары — 24 SVG

Рисует `scripts/make_avatars.py`, холст 200×200. Генератор собран из «кирпичиков»:
`head()`, `eyes()`, `mouth()`, `top()` (уши, рога, антенны, плавник), `extras()`, `blush()`.
24 персонажа получаются комбинациями, а не 24 кусками ручной вёрстки; индивидуальные правки
живут в словарях `SPECS`, `EAR_INNER`, `EAR_OUTER`, `EYE_TUNING`, `MOUTH_TUNING`.

Рисуем сами, чтобы не зависеть от чужих лицензий и работать без интернета.

**Порядок списка `AVATAR_PRESETS` в `db.py` = порядок в сетке выбора** у ребёнка:
сначала звери, потом сказочные, потом техника и космос. Ключи из первых версий сохранены:
в базе у детей уже записан выбранный пресет, и смена набора ничего не ломает.

Главный критерий качества: аватары должны различаться в **38 px** — это их размер
в строке рейтинга. Поэтому у персонажей разные силуэты, а не только цвет.

### Фотографии призов — 8 WebP

Качает `scripts/fetch_prize_photos.py`, приводит к 800×600 на белом фоне.

работает, тогда как `upload.wikimedia.org` отдаёт 429. Это учтено в скрипте.

Любое фото учитель заменяет своим снимком прямо в панели.

plus close check pencil trash refresh camera printer qr eye eye-off
clipboard import export calendar history logout key lock warning info
arrow-left arrow-right chevron-down minus-circle send

Размеры задаются классами: `.ic` (базовый), `.ic-sm`, `.ic-lg`, `.ic-xl`.

## 11. Развёртывание

Подробные шаги — в README, раздел «Развёртывание на сервере». Здесь — общая картина.

```
          интернет
             │ https://домен/stars/...
             ▼
    ┌──────────────────┐
    │ nginx на хосте   │  location /stars/ { proxy_pass http://127.0.0.1:8000/; }
    │ (сертификат,     │  client_max_body_size 6m
    │  другие сайты)   │
    └────────┬─────────┘
             │ http, префикс уже срезан
             ▼
    ┌──────────────────────────────┐
    │ контейнер school-stars       │  порт только на 127.0.0.1
    │  uvicorn --proxy-headers     │
    │  FastAPI + Telegram-бот      │
    └────────┬─────────────────────┘
             │
        том ./data:/app/data   ← база, секрет, фотографии
```

Что проверить при переносе:

1. `bash deploy/check-server.sh` — где nginx (хост или контейнер), свободен ли порт 8000.
   От ответа зависит, какой из двух конфигов брать.
2. Код доставляется **через git**. `.env` в репозитории нет — он создаётся на сервере
   из `.env.example`, и токен бота туда вписывается руками.
3. `--proxy-headers --forwarded-allow-ips *` в `Dockerfile` обязательны: без них приложение
   за nginx считает соединение незащищённым.
4. Бэкап — `bash deploy/backup.sh`, в cron на 3:30. Восстановление: распаковать `data/` обратно.
5. Образ собирается от пользователя UID 10001, не от root.

**Что не проверено локально и честно отмечено:** сборка Docker-образа (Docker на рабочей
машине не установлен, нет прав администратора) и живая работа бота (токена пока нет).
Обе проверки — первым запуском на сервере.

## 12. Как это проверялось

Регрессионный набор — `smoke.py`, 57 проверок: закрытость эндпоинтов, вход учителя,
школы и каскадное удаление, одноимённые классы в разных школах, карточки с QR, кабинет
ученика, лимиты урока, призы с фотографией, подстановка `{{BASE}}` и `{{ICONS}}`.

Скрипт принимает базовый адрес, поэтому один и тот же набор прогоняется дважды:

```
python smoke.py http://127.0.0.1:8000           # в корне
python smoke.py http://127.0.0.1:8001/stars     # на подпути, через прокси
```

Второй режим — мини-прокси `prefix_proxy.py`, который срезает `/stars` точно так же, как nginx.
Это единственный способ проверить подпуть, не выходя на сервер.

## 13. Куда смотреть при типичных задачах

| Задача | Файлы |
|---|---|
| Добавить поле ученику | `db.py` (`DEFAULT_DB` + `migrate`), `routers/teacher.py`, `static/js/teacher.js` |
| Изменить лимит звёзд | `config.py` (`MAX_*`), дубль-подсказка в `static/js/teacher.js` |
| Новый эндпоинт учителя | `schemas.py` → `routers/teacher.py` → вызов в `teacher.js` |
| Новая иконка | `static/img/icons.svg` (новый `<symbol id="i-…">`), затем `icon("…")` в JS |
| Поменять цвета или шрифты | только `static/css/theme.css`, блок `:root` и `@font-face` |
| Перерисовать аватары | `scripts/make_avatars.py`, затем список в `db.py` |
| Заменить фото призов | панель учителя, либо `scripts/fetch_prize_photos.py` |
| Поменять текст бота | `backend/bot/handlers.py` |
| Переехать на поддомен | `URL_PREFIX=` в `.env` + конфиг nginx. Код не трогать |
| Разобраться, почему 404 на статике | §3.3 — скорее всего, кто-то вернул `root_path` |

## 14. Что стоит знать о границах системы

- **Один процесс.** Горизонтально не масштабируется: два экземпляра начнут писать в один JSON.
  Для школы это не ограничение, для района — повод переходить на СУБД.
- **Нет ролей внутри учителя.** Один пароль = полный доступ ко всем школам.
  Если школ станет много и у каждой свой учитель, понадобятся отдельные учётные записи.
- **Нет журнала действий.** История есть у звёзд (`student.history`), но кто именно
  удалил класс — нигде не записано.
- **Витрина призов не резервирует товар.** Списание звёзд делает учитель руками,
  когда выдаёт приз. Это осознанно: решение о выдаче всё равно за человеком.
